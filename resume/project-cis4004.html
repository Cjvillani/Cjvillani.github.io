Overview

A community recipe platform, built as a team.

RecipeStack is a full-stack MERN web application I helped build with a team of five over the course of a semester. Users can register, sign in, publish recipes with ingredients and directions, upvote and downvote community submissions, earn “karma” based on their contributions, and climb a public leaderboard. Admins have a separate role with moderation tooling. The entire system runs on Express and MongoDB on the back end, with a React and Vite front end proxying API calls through to the server in development.

My Contributions

What I built

“My Recipes” feature — end-to-end

  • Built a new authenticated page that queries the recipes API with an author filter so logged-in users see only the content they’ve published.
  • Designed a card grid with cover images, summaries, and current rating, matching the app’s shared visual system.
  • Implemented inline editing: the card transforms into a controlled form for title, summary, image URL, ingredients, and directions, then issues a PUT to the API and optimistically updates local state on success.
  • Added a confirm-first delete flow with per-row loading state and graceful error handling so a failed request never leaves the UI in an inconsistent state.

Admin page visual unification

  • Brought the admin portal into the team’s new visual system after a mid-project restyle, rebuilding the header gradient, section cards, item rows, and destructive-action buttons so moderation felt like part of the same product.
  • Preserved all existing functionality — user listing, recipe listing, and safe deletion with confirmation — while upgrading spacing, typography, and interaction states.

Team workflow & delivery

  • Worked inside a protected-branch Git workflow: no direct pushes to main or dev, feature branches per contributor, and all merges via pull request.
  • Resolved branch drift by merging dev into my feature branch, renaming branches cleanly, and opening PRs targeting dev.
  • Coordinated with teammates over Discord through the typical rhythms of a real project — schema changes, shared styling modules, and dependency on work other people were shipping in parallel.

Stack

Technical stack

Front end

  • React 18
  • Vite
  • Hand-authored CSS-in-JS
  • Fetch API with async/await

Back end

  • Node.js
  • Express 5
  • Mongoose ODM
  • REST API with versioned routes

Data

  • MongoDB (local)
  • User, Recipe, and voting schemas
  • Role-based access (user / admin)

Tooling

  • Git / GitHub pull-request flow
  • Nodemon for live reload
  • Vite proxy for /api in dev

Takeaways

What I took from this

  • How to land cleanly in a codebase I didn’t start — reading other people’s schemas and route handlers before touching anything, then contributing in the existing style.
  • Why a disciplined branch workflow matters. On a team of five, the difference between “I think it works” and “the PR is green and ready to merge” is where the real work happens.
  • How to build features that feel finished — confirmations before destructive actions, loading states on every async button, and error handling that surfaces a message instead of failing silently.
